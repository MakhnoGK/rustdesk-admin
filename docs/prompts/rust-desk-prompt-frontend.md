The API server (`apps/api`, port 21114) has two namespaces:

- **RustDesk-facing** routes (`/api/login`, `/api/ab/*`, `/api/audit/*`, `/api/heartbeat`, `/api/sysinfo`) used only by RustDesk clients;
- the **admin API** (`/api/admin/*`) used only by this panel: cookie-authenticated, role `ADMIN`.

It turns RustDesk connection audit records into sessions (`ACTIVE` / `CLOSED` / `TIMEOUT` / `UNKNOWN`), keeps a device registry from heartbeats, manages personal and shared address books with tags, users and tokens, and computes statistics in the database.

The admin panel is the human-facing UI for that admin API: sign-in, live sessions, session history and analytics, devices, address books and tags, users and their tokens, and remote disconnect.

If `apps/api` or `packages/*` are missing, do not create or modify them. Build `apps/web` against the expected contract below, and say so in the report.

## Architectural boundary (critical)

The panel talks **only** to `/api/admin/*` (and `/api/health/*` if useful).

It must NOT:

- call RustDesk-facing endpoints (`/api/login`, `/api/ab/*`, `/api/audit/*`, `/api/heartbeat`, `/api/sysinfo*`);
- talk to RustDesk `hbbs`/`hbbr` or emulate a RustDesk client;
- offer actions RustDesk cannot perform: no "connect", "view screen", or "send file".

**Remote disconnect is real but asynchronous.** The API queues a disconnect, the device receives it in its next heartbeat (every ~3 s while it has live connections), and the session closes when the device reports the close. The UI must show this as states — *requested → delivered → closed*, or *expired* if the device never picked it up — and never as an instant result.

## RustDesk facts that affect the UI

Verified against the RustDesk client source (`rustdesk/rustdesk` master, commit `e5bc204`, 2026-10-03) and reflected in the API's data model:

- The **target** of a session is the device that reported it; the **initiator** becomes known only after authentication. A session can therefore have **no initiator** (authentication failed or still in progress). Render it explicitly ("Unknown initiator" / "Not authenticated"), never as a blank cell or a crash.
- The connection type is a raw integer from the client. Show the API's label if it provides one, otherwise the raw value. Do not invent a mapping.
- Some durations are **estimated** (`durationEstimated: true`): the session was closed by heartbeat reconciliation or by timeout, not by a close event. Mark them visibly (for example "≈ 1h 05m" with a tooltip that gives the `closeReason`).
- Address books are personal (one per user) or shared (with per-user rules: 1 read-only, 2 read/write, 3 full control). Tags belong to a book and have an ARGB integer color.
- Address-book credentials (`password`, `hash`) are never readable through the admin API; it exposes `hasPassword` only. A shared book's password can be set (write-only).

### Expected admin API (verify against the contract)

Conventions: lists take `?page&pageSize` (max 200) and `?sort=field:asc|desc` and return `{"data", "total", "page", "pageSize"}`. Errors are `{"error": {"code", "message", "details"?: [{"field", "message"}]}}`. Timestamps are ISO-8601 UTC; durations are integer seconds.

- **Auth**: `POST /api/admin/auth/login` `{username, password}` → `{user, expiresAt}` + httpOnly cookie; `POST /api/admin/auth/logout`; `GET /api/admin/auth/me`.
- **Users**: `GET|POST /users`, `GET|PATCH|DELETE /users/:id`, `POST /users/:id/password`.
- **Tokens**: `GET /users/:id/tokens`, `DELETE /tokens/:id`.
- **Devices**: `GET /devices`, `GET /devices/:uuid`.
- **Address books**: `GET|POST /address-books`, `PATCH|DELETE /address-books/:guid`, `GET|PUT /address-books/:guid/shares`.
- **Peers**: `GET|POST /address-books/:guid/peers`, `PATCH|DELETE /address-books/:guid/peers/:peerId`.
- **Tags**: `GET|POST /address-books/:guid/tags`, `PATCH|DELETE /address-books/:guid/tags/:name`.
- **Sessions**: `GET /sessions`, `GET /sessions/active`, `GET /sessions/:id`, `POST|GET /sessions/:id/disconnect`.
- **Stats**: `GET /stats/summary`, `GET /stats/timeseries?bucket=hour|day`, `GET /stats/top?by=initiator|target`.
- **Audit**: `GET /audit-events?kind=conn|file|alarm`.
- **System**: `GET /system/info` (version, `sessionTimeoutMinutes`, `heartbeatGraceSeconds`, `deviceOnlineThresholdSeconds`, `disconnectTtlSeconds`).

All paths except auth are relative to `/api/admin`.

## 2. Authentication

- The session lives in an **httpOnly cookie** set by the API. The frontend never sees, stores, or decodes a token: no `localStorage`, no `sessionStorage`, no `Authorization` header.
- Login page: username + password → `POST /api/admin/auth/login`. Show the API's error message on 401/403/429.
- App start: `GET /api/admin/auth/me` decides between the app and the login page (a route loader, not a flash of protected content).
- Keep `expiresAt`; warn a few minutes before expiry and redirect to login at expiry with a "Session expired" message.
- On any 401: clear the query cache and redirect to `/login?redirect=<current path>`. After login, return to the redirect target — same-origin relative paths only (no open redirect).
- Logout: `POST /api/admin/auth/logout`, then clear the query cache regardless of the result.
- CSRF is handled by the API (SameSite=Strict cookie + `Origin` check). The browser sends `Origin` on same-origin POST/PATCH/PUT/DELETE automatically; do not strip it in the nginx or Vite proxy.
- A 403 renders a dedicated "No access" state.

## 11. Error handling

- Parse `{"error": {"code", "message", "details"}}` into a typed `ApiError`.
- Status mapping:
  - 422 → field errors from `details`; 400 → form-level alert;
  - 401 → the logout flow from section 2;
  - 403 → "No access" state;
  - 404 → not-found state;
  - 409 → field or conflict message;
  - 429 → toast, honoring `Retry-After`;
  - 5xx / network → error state with retry.
- Never show stack traces, raw HTML error pages, or internal error text.
- Query errors render inline; mutation errors become toasts or form errors — never both for one error.
- TanStack Query retries: none on 4xx; limited, with backoff, on network errors and 5xx.
